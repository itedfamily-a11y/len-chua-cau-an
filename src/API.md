# "Lên Chùa Cầu An" — module contract (read this first)

The game is ONE `index.html`, built by `node build.js` from `src/shell.html` + every `src/NN-*.js` file
concatenated (sorted by name) into a single `<script type="module">` (`build.js` normalises CRLF to LF in `shell.html` and in every module with `.replace(/\r\n/g, '\n')` because a few sources are still CRLF, `.trim()`s each module, and takes `ONLY=00,05,…` for a subset build and `OUT=file` for another output name; it injects the modules at the `//@@MODULES@@` marker of the shell). Three.js r160 is imported once in
`00-core.js` (`import * as THREE from 'three'`). Every module file must contain exactly ONE top-level
declaration: `function installXxx(G) { ... }` — no imports, no other top-level code/const/let (they would collide).
Boot order (`99-boot.js`): buildWorld → buildWorld2 → buildWorld2Geo → buildChinhDien (18; it calls buildBanTho from 18-ban-tho.js for the altar, which calls banThoAtlas from 18-ban-tho-tranh.js — hoisted function declarations of the one module) → buildCungDinh (19) → buildDienPhu → buildDecorInside → buildGateSign → buildScenery → installFx → installHauKy (07-hau-ky.js, step "hậu kỳ") → installPlayer → installAudio → installMusic → installKinhVan (21) → installCrowd →
installActivitiesA → installActivitiesB → installNgoiTungKinh (45) → installActivitiesC → installDiChuaChung (22, step 'đi chùa chung', last) → G.start(). Each install is wrapped in try/catch.

Hard rules
- No external assets: no images/models/audio/fonts URLs; the only network loads are Three.js and its `three/addons/` from the jsDelivr CDN (import map in `shell.html`) — plus ONE agreed exception since 2026-11-08: the P2P library Trystero 0.26.0 (import-map entry `"trystero"`, jsDelivr `+esm`, exact version), which `22-di-chua-chung.js` `import()`s ONLY after the player turns on "Đi chùa cùng mọi người" (off by default, so nobody downloads it unasked). Reason: real many-player presence needs a signalling path and WebRTC glue that cannot be synthesised in-page; Trystero gives that without any server of ours, without API keys and without collecting anything. No other library may be added without the user's explicit consent. Canvas textures and Web Audio synthesis, plus two payloads that are EMBEDDED as base64 in the source (not downloads): the background music of `11-music.js` (AAC, about 2.7 MB of the 3.9 MB page; its own header says the tracks are the author's copyrighted recordings, fine for personal play, and need permission or replacement before a public release) and one JPEG for the gate sign (`14-bien-bao.js`, `photoData()`).
- All UI text Vietnamese (with diacritics). Gentle, respectful tone: no jokes about the Buddha, no monsters,
  no win/lose, no harsh ranking. Never claim prayers are guaranteed to come true. Never mention money/donations.
- User text (names, prayers) is ALWAYS inserted with `textContent` / canvas fillText — never innerHTML.
- Per-frame code (`G.onUpdate`) must not allocate: reuse module-level Vector3/Matrix4/Object3D temps.
- Dispose textures/geometries/materials you create when the object is removed.
- Mobile first (portrait ~390×844), tap targets ≥ 44px; desktop also works (mouse + keyboard).
- Comment style: a short Vietnamese header comment at the top of each section (match existing files).
- Coordinates: meters, y up. Character "yaw": forward = (sin yaw, 0, cos yaw); facing north (−z) is yaw = π.
  `G.util.yawTo(x0,z0,x1,z1)` gives the yaw that faces from point 0 to point 1.

  - **Frame-buffer check and fallback chain 2 → 1 → 0.** Some mobile GPUs report the float extensions but cannot complete a half-float (especially MSAA) framebuffer, which used to leave the whole hall black. `build()` therefore validates every scene target with `fboOk(rt, true)` before using it: `checkFramebufferStatus === FRAMEBUFFER_COMPLETE`, then a test triangle is drawn into it (clear, draw and MSAA resolve) and the GL error flag is read (`glErr()` first clears stale flags, then reads and clears all; a lost context counts as OK and is re-checked on `webglcontextrestored`). If even 0 samples fails, `P.level--` and `P.maxLevel = min(maxLevel, level)`: level 2 → 1 → 0, and `reason` = 'GPU không nhận mục tiêu half-float — hạ xuống mức N' (N = 1) or '— vẽ thẳng' (level 0). At the end of `prewarm()` `fboAll()` re-checks the GL error flag and every target of the chain (rtM, rtA, the bloom bright / horizontal / vertical targets and the three GTAO targets); on failure `degrade(why)` lowers the level once (same warn once, same `reason` pattern), rebuilds (which validates again) and pre-warms again. Three more ways down the chain: an exception inside `prewarm()` counts as "not OK" (`resetState()`, then `degrade()`); `webglcontextlost` counts losses (`lostN`) and `webglcontextrestored` first lowers the level to 1, and to 0 from the second loss on (`P.reason` "mất ngữ cảnh WebGL — hạ xuống mức n"), before `build()` + `prewarm()`, so a memory-pressure loss cannot loop; and a `G.save.data.lowQ` timestamp younger than 7 days caps `maxLevel` at 1 at install (a machine that was slow recently never starts on the heaviest chain).
